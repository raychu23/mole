# Argdown fixtures: oracle JSON provenance (T48)

`support-attack.argdown` is argdown-core's own `ModelPlugin.spec.ts` test case ("can create
statement relations and ignore duplicates", `packages/argdown-core/test/ModelPlugin.spec.ts`,
retrieved from the shallow clone at `~/.hermes/cache/scratch/core-audit/argdown`), run in the
default (non-STRICT) interpretation mode.

`undercut.argdown` is a minimal variant built from the same repo's lexer/model vocabulary
(outgoing-undercut `<_` token, `packages/argdown-core/src/lexer.ts:214-220` /
`src/plugins/ModelPlugin.ts` OUTGOING_UNDERCUT handler), not copied verbatim from an existing
example (no `.argdown` example file in the repo demonstrates undercut alone without a full PCS
reconstruction -- `legalisation-softdrugs.argdown` only mentions "undercut" in prose comments,
never the syntax).

`*.oracle.json` were generated by running the real `@argdown/core` package (MIT, v2.0.1, added as
this package's devDependency) directly, with `ParserPlugin` + `DataPlugin` + `ModelPlugin`
(the same plugin set `ModelPlugin.spec.ts` itself uses), and dumping `result.relations` (from/to
titles + relationType) and `Object.keys(result.statements)` / `Object.keys(result.arguments)` to
JSON. The generating script is not kept in the repo (a throwaway `node --input-type=module` one-
liner); re-generate by running the same three plugins on the fixture text and serializing
`result.relations.map(r => ({from: r.from?.title, to: r.to?.title, relationType: r.relationType}))`
plus `Object.keys(result.statements ?? {})` / `Object.keys(result.arguments ?? {})`.
