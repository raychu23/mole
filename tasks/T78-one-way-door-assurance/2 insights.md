## Notes / limits (INFERENCE labelled)

- **Folder grouping chose `scope:` anchors, not the record file's directory.** All `.mole/decisions/*.md` records live in one flat directory (`loadMoleDecisions` reads it non-recursively), so "assured share per folder" only means something if "folder" = the code folder(s) a decision *governs* (its `scope` anchors), not where its `.md` file sits. INFERENCE: the task text doesn't disambiguate this; I inferred the scope-anchor reading because it's the only one that produces a non-trivial per-folder metric, and it reuses the `Anchor`/`scope` concept Mole already has. A record with no `scope:` falls back to its own file's folder so it's never silently dropped from every report.
- **Per-link assurance fields are a new `assurance:` YAML list** on the decision record (`to`, `doubt`, `provenance`, `author`, `approver`, `alcoa` as a comma-joined subset of the 9 ALCOA+ words, `reverify_by`), modelled on the existing `evidence:` list-of-maps convention in `graph.ts`/`records.ts`. INFERENCE: the contract says "per-link" but Mole's `GraphEdge` has no front-matter home of its own (edges are derived from a record's relation fields, e.g. `supersedes:`); attaching assurance to the *decision record* with an explicit `to` per entry is the smallest change that still identifies which link each doubt/provenance/ALCOA+/re-verify entry is about.
- **"Assured" is all-or-nothing per link**: doubt type + provenance + author≠approver + all 9 ALCOA+ attributes + a `reverify_by` that is not in the past. A link missing even one of these is unassured, not partially-assured — simplest rule that matches "regulated-grade rigor," open to loosening later with evidence from real use.
