Note: the exported repo legitimately ships zero test files (every package's test/ dir is excluded by
export-public.mjs, dev-only fixtures). vitest.config.ts now sets `passWithNoTests: true` (T87 review fix) so
this is a real pass, not a false positive -- the private repo always has ~1,350 real tests and runs them
exactly as before (verified separately: `npm run check` in the private repo, 1347 passed | 19 skipped).

Root cause of the original failure (HIGH): root tsconfig.json and packages/daemon, packages/steer,
packages/mcp's tsconfig.json referenced packages/agentstate and packages/coverage, which export-public.mjs
excludes (author-machine workflow, not an end-user Mole feature -- see that file's own comment). Fix:
daemon/steer/mcp's compile-time dependency on those two packages' functions is now a lazy, non-literal dynamic
import (packages/mcp/src/optional-agentstate.ts, packages/mcp/src/optional-coverage.ts,
packages/steer/src/index.ts, packages/daemon/src/cli.ts) instead of a static import -- tsc only statically
resolves a dynamic import() whose argument is a string literal (verified empirically against tsc 5.9.3), so a
variable specifier never needs the package to be present to type-check; export-public.mjs now also rewrites
the dangling tsconfig project references and package.json dependency entries. A second, same-shape bug was
also found and fixed along the way: root tsconfig.json also referenced packages/bench (a private, dev-only
benchmark harness also excluded by export-public.mjs), causing the same TS5083.
