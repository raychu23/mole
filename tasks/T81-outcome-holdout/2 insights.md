## Notes / limits (INFERENCE labelled)

- **Verdict (`result: confirmed|contradicted|inconclusive`) is human-authored, never computed.** INFERENCE: the contract says "an outcome that contradicts its prediction," which could be read as Mole comparing `expected` vs `observed` text itself. I chose NOT to do that — there is no reliable, model-free way to judge whether free text "contradicts" other free text, and the contract elsewhere requires "no model calls." The person who records the outcome states the verdict explicitly, the same way `door: one-way` is never inferred (T78's own prior-art finding). This is the single most load-bearing choice in the design; if it's wrong, the fix is additive (a new optional comparison helper), not a rewrite.
- **"Due" vs "overdue"**: `due = checkAt <= today && no outcome`; `overdue = checkAt < today && no outcome` (so `overdue` is always a subset of `due`, and `daysOverdue` is only set when overdue). INFERENCE: the task text uses "due/overdue checks" without defining the boundary at exactly `today`; I chose `<=` for due (today's own check is due today) and `<` for overdue (strictly in the past) as the smallest, most literal reading.
- **`rollout:` requires both `treated:` and `holdout:`** to produce a `Rollout`; either one alone is reported in `malformed` (block `rollout`) and `entry.rollout` stays `undefined`. This matches D66's own wording ("names the treated scope and a holdout scope") and the contract's own stop clause — no assignment/statistics, just the two names, never guessed from one side alone.
- **`prediction:` is the opt-in gate**, same role `door: one-way` plays for assurance — a decision record with no `prediction:` block never appears in `mole outcomes` at all (not an error, not a malformed entry).
- **The suggested-incident draft is never written anywhere by this code path.** `outcomesReport`/`outcomesCli`/the MCP tool are all read-only; `draftIncidentRecord` only builds a string. Verified in the demo: `ls .mole` after running the report on all 3 fixtures (one contradicted) shows only the pre-existing `decisions` directory, no `incidents`.
- Per boundary, `prediction`/`outcome`/`rollout` were added only to `types.ts` + the new `outcomes/` module; `graph.ts`'s `GraphNode` builder was NOT touched (same approach `assurance/report.ts` takes for its own `assurance:` field — re-parse front matter from the raw file text instead of growing `GraphNode`).

Also not run: the repo-root `npx vitest run` (would pick up every package including slow/unrelated bench suites); ran `packages/decisions` + `packages/mcp` instead, which cover every file this task touched plus the MCP tool-annotations contract test.
