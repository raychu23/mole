# Prior art (R0) — T37 plugin serves the decisions

Searched 2026-10-29. Field term: "agent memory / project rules for coding agents", "decision records with citations", "hooks-based context injection".

## 1. Claude Code hooks: SessionStart additionalContext, PreToolUse, Stop

- **Source**: Anthropic, Claude Code docs, "Hooks reference" — https://docs.anthropic.com/en/docs/claude-code/hooks (fetched 2026-10-29; also https://code.claude.com/docs/en/hooks mirrors it).
- **What it says we can rely on**:
  - `SessionStart` fires at session begin/resume; the only output it accepts is `hookSpecificOutput.additionalContext` (text injected before the first prompt) plus `sessionTitle`/`watchPaths`/`reloadSkills`. No decision control (can't block). "SessionStart runs on every session, so keep these hooks fast."
  - `PreToolUse` fires before a tool call and CAN block (`permissionDecision: "deny"`, exit code 2), but it can also just add `additionalContext` next to the tool result without blocking (`permissionDecision` omitted / `"allow"`). Matcher syntax `"Edit|Write"` scopes it to specific tools.
  - `Stop` fires when Claude finishes responding; accepts `systemMessage` (shown to the user) and `hookSpecificOutput.additionalContext` (fed back to Claude, which can make it continue once). It "informs and never blocks" unless `decision: "block"` is set — we never set it (non-goal: never block).
  - `additionalContext` over ~10,000 chars gets spilled to a file by Claude Code itself; the existing Mole hooks additionally self-clip to `MAX_CHARS = 9500` so the full text always reaches the model inline. M31a's 1,500-char budget is well under both ceilings — SessionStart's decisions block must be far more disciplined than "fits in 10k", so we size it deliberately.
  - A hook that exits non-zero without valid JSON stdout is a "non-blocking error" (Claude proceeds) EXCEPT PreToolUse where exit 2 blocks — this is exactly why Mole's hook convention (`lib.mjs` comment, "a hook never fails the session: any problem = exit 0 with no output") matters: we must never use exit 2 by accident.
- **What we borrow**: the existing Mole plugin (`plugins/claude-code/scripts/session-start.mjs`, `stop.mjs`, `lib.mjs`) already follows this contract for notes (T11), collisions (T21) and claims (T24). T37 extends the same `additionalContext`/`systemMessage` channels with a decisions block, and adds a new `PreToolUse` hook on the `Edit|Write` matcher that only ever adds context, never denies.
- **Gap we fill**: Claude Code has no built-in concept of "decision records that govern these lines" — that's Mole's own `.mole/decisions` graph (T29/T27), already built. T37's job is wiring, not inventing a new hook mechanism.

## 2. Cursor rules (`.cursor/rules/*.mdc`) and `AGENTS.md` conventions

- **Source**: Cursor Docs, "Rules" — https://cursor.com/docs/context/rules and https://cursor.com/docs/rules (fetched 2026-10-29); "Customizing agents" — https://cursor.com/learn/customizing-agents (fetched 2026-10-29).
- **What it says**: project rules are markdown-ish files, version-controlled, "seen at the start of every conversation" (same cadence as SessionStart), scoped by path glob or "always apply"; `AGENTS.md` is the plain-markdown fallback Cursor reads the same way. Explicit anti-pattern: **"Don't copy entire style guides… rules consume unnecessary context and may confuse the agent"** and **"Keep your rules minimal and high quality."** Precedence when rules conflict: Team > Project > User.
- **What we borrow**: the 1,500-char budget and "each decision as one rule line with its flag and owner" directly follows this guidance — a short, scoped, per-file set of rules beats dumping the whole decision graph. Decisions that don't govern files in play are left out entirely (scoping by path, like Cursor's glob-scoped rules), rather than always-apply.
- **Gap we fill**: Cursor/AGENTS.md rules are static text a human writes and commits; Mole's decisions are already live records with flags (T29) computed from git + code, so the "rule" text is generated per session from current flag state, not hand-maintained.

## 3. GitHub Copilot Memory's citation checks

- **Source**: GitHub Docs, "About GitHub Copilot Memory" — https://docs.github.com/en/copilot/concepts/prompting-and-context/copilot-memory (fetched 2026-10-29); GitHub Blog, "Building an agentic memory system for GitHub Copilot" — https://github.blog/ai-and-ml/github-copilot/building-an-agentic-memory-system-for-github-copilot/ (fetched 2026-10-29).
- **What it says**: every repo-level memory is stored with citations (file:line) that "support" the fact; before using a memory, Copilot "verifies the citations in real-time, validating that the information is accurate and relevant to the current branch." Their stress test: "deliberately seeded repositories with adversarial memories... agents consistently verified citations, discovered contradictions, and updated incorrect memories." Memory is agent-created from a PR/session and shared cross-agent (code review -> coding agent -> CLI).
- **What we borrow two things directly**:
  1. **Citation-before-use**: Mole's decisions already carry `scope` anchors (file/symbol/folder) and a citator (T29 `computeFlags`) that checks each anchor against git — this is the same "verify the citation against the current branch" idea, except computed deterministically by code (R6) instead of by a model's judgment call. T37 reuses `computeFlags`'s existing red/yellow/green/grey verdict as the "is this decision still accurate" signal, rather than re-deriving it.
  2. **Cross-surface sharing**: Copilot's memory crosses code review -> coding agent -> CLI surfaces. T37's requirement ("same content from the MCP server... so Codex, Cursor and Hermes get it too") is the same shape: one source of truth (`@mole/decisions` + the file-filter we add), reachable from both the Claude Code plugin hooks (shelling to the `mole` CLI) and the MCP tool (`mole_decisions` with a `files` argument) so any MCP-capable harness gets identical governing-decision data.
- **Key difference we keep (per Mole's tenet-1)**: Copilot's memories are *written by a model's judgment of what's worth keeping*, and their own docs caution "this is a judgment Copilot makes, rather than a guarantee enforced by the system." Mole's decisions are the opposite direction: *people* write `.mole/decisions/*.md` (reviewed like a PR per D31), and the agent's job is only to surface them and report where they were touched — never to author or edit them. This is the literal ask (Raymond 10-29 15:30): "Mole's plugin carries the PEOPLE's decisions to the agent and the agent's effect on them back to the person" — the inverse direction of Copilot Memory / claude-mem / ai-memory, which carry what the *agent* did forward to the next agent.

## Method picked

- SessionStart: match each file "in play" (same `filesInPlay()` used by T11 notes: uncommitted + last 3 commits) against every decision/tenet's `scope` anchors (file exact match, `path#Symbol` by path prefix, `folder/` by path prefix), using the already-exported `@mole/decisions` `loadGraph` + `computeFlags` (read-only, boundary-respecting) from the MCP server, and a lightweight re-parse of `.mole/decisions/*.md` front matter (scope + approver only) from the plugin hook scripts (no new TS dependency for the hook scripts, consistent with `lib.mjs`'s "no dependencies" convention) joined against `mole decisions --json` for flags.
- PreToolUse: same file-to-decision match against the single `tool_input.file_path`, gated by a per-session "already added this decision id" set persisted next to the existing session file (`sessionFile()` in `lib.mjs`), so a decision is added at most once per session (never a second time, never a block).
- Stop: decisions whose scope anchors fall inside the session's diff files (reuse `checkResult`'s existing diff-file list) + `mole rules` (T27) violations found in that diff, both already exported as deterministic JSON by `@mole/decisions`.
- M31a/M31b keys are built BY HAND from `git log`/`git diff` on the real 10-29 ledger task branches and the real `.mole/decisions/*.md` scope fields, read with a separate throwaway script that only parses YAML front matter — never by running the hook code under test (R1/key independence).
